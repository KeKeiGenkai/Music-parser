# Доступ к сервису в локальной сети

## Текущая схема

```
[Интернет]                    [Роутер]
     |                             |
     |  (порт 8080 НЕ проброшен)   |  ← Доступа извне нет
     |                             |
     +-----------------------------+
                    |
              [Твой компьютер]
                    |
         +----------+----------+
         |                     |
    [Сервис :8080]        [Бот (позже)]
         |
         +--- localhost (бот обращается сюда)
         +--- 192.168.x.x (устройства в сети обращаются сюда)
```

## Доступ внутри сети

Сервис **уже доступен** из локальной сети. Нужно знать IP компьютера:

**Windows:**
```powershell
ipconfig | findstr IPv4
```

**Или:** Настройки → Сеть → Свойства соединения → IPv4-адрес

Обычно это `192.168.1.x` или `192.168.0.x`.

С других устройств в той же сети WiFi/LAN открой:
```
http://192.168.1.XXX:8080
```
(подставь свой IP вместо XXX)

## Бот на том же компьютере

Бот обращается к сервису по `http://127.0.0.1:8080` или `http://localhost:8080`.

## Безопасность: нет доступа из интернета

- Роутер по умолчанию **не пробрасывает** порты внутрь — порт 8080 не открыт в интернете.
- Если проброс не настроен, сервис доступен только в LAN и localhost.

## Опционально: явно запретить внешний доступ

Если нужна дополнительная защита (например, когда роутер в режиме DMZ), можно привязать порт только к LAN:

В `docker-compose.web.yml` заменить:
```yaml
ports:
  - "8080:8080"
```
на (подставь свой LAN IP, например 192.168.1.100):
```yaml
ports:
  - "192.168.1.100:8080:8080"
```

Тогда localhost перестанет работать. Чтобы сохранить и localhost, и LAN, оставь `"8080:8080"` — этого достаточно для большинства случаев.
